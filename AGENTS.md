# ADR Architecture Governance

This OpenCode profile works with the architecture repository configured as `ADR_REPO` in `config/tooling.mk` (by default, `../acm-adr`).

## Authority

- Approved ADRs under `docs/adrs/ai/approved/` in the configured repository are accepted architectural authority.
- Proposed ADRs under `docs/adrs/ai/proposed/` in the configured repository are drafts, not accepted architecture.
- Diagrams under `docs/diagrams/` in the configured repository are supporting artifacts and must not override approved ADRs.
- Implementation evidence describes what exists; it does not silently replace accepted architecture.

When implementation or a diagram conflicts with an approved ADR, report drift or conflict explicitly.

## Human approval boundary

AI agents may analyze, draft, revise proposed ADRs, review, audit consistency, and maintain diagrams through permitted tooling.

AI agents must not approve an ADR, move it into the approved set, or declare a draft authoritative.

## Artifact ownership

- `architect` owns architecture reasoning, decisions, orchestration, and standalone diagram semantics.
- `adr-writer` owns creation and mutation of proposed ADR files, including embedded Mermaid based on established semantics.
- `adr-reviewer` reviews proposed ADRs but does not modify them.
- `architecture-finder` performs targeted retrieval only.
- `consistency-auditor` performs cross-ADR consistency analysis only.

## Generated runtime

`AGENTS.md`, `opencode.json`, and `.opencode/` are generated by this framework. Edit profile sources under `profiles/adr/`, then run `make render`.
